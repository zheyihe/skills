# 诊断与验证操作卡

这是从诺曼框架推导的实践工具，不是他的原文或官方清单。按问题选择一张卡，不必全部运行。

## A. 界面、物品与交互

把描述转成一次具体行动：谁，在什么环境，为了什么目标，看到什么，做了什么，得到什么结果。

| 检查 | 要获取的证据 | 可尝试的干预 |
|---|---|---|
| 概念模型 / 系统映像 | 用户以为产品如何工作；界面、说明、反馈实际传达什么 | 让状态、对象关系、可逆性和规则一致可见 |
| 可发现性 / 指示符 | 首次接触者是否找到行动入口；是否误读静态文本为控件 | 命名、位置、形状、约定和可访问标签共同指示行动 |
| 可供性 | 对特定人的身体与能力，什么行动实际上可能 | 调整操作范围、设备适配、替代通道；不把“看起来能点”当成全部 |
| 映射 / 约束 | 控制与结果如何对应；是否存在危险、无效或不必要选择 | 空间/语义映射、合理默认值、必要约束 |
| 反馈 / 评估鸿沟 | 用户能否分辨已收到、进行中、完成和失败 | 区分状态；对实际结果反馈，避免仅按钮动画 |
| 头脑与环境中的知识 | 哪些规则、位置、步骤必须记住；中断后如何恢复 | 外部记忆、可见进度、上下文提示 |

确认“用户不知道怎么做”与“用户知道但当前无法做”的区别。给出改变一个机制的最小原型；让代表性用户完成真实任务，记录首次行动、错误、恢复、解释结果的能力。没有原型或行为观测时，结论标为待验证假设。

## B. 错误与可靠性

1. 重建错误前后：信息、目标、动作、系统状态、中断、时间压力、交接。
2. 区分 **slip（执行失误）**：意图正确却做错动作，和 **mistake（认知错误）**：目标、规则或模型本身有误。证据不足时不强分。
3. 对失误优先检查动作区分、模式可见性、约束和恢复；对认知错误检查规则、概念模型、解释与情境。
4. 从界面追到排班、激励、资源与交接。“人为错误”是继续调查的起点；系统解释不能证明具体个体必然没有责任。
5. 先预防严重错误，再让错误可发现、可恢复。可撤销、草稿、恢复、审阅或分级确认按后果选择；不默认每个操作都弹确认。

验证时看误操作机会、发现率、恢复成本与新引入的延迟。重大后果须用领域专家和真实安全要求核查，不能只凭设计直觉判断。

## C. 复杂性与情感

先列出必须支持的活动，再区分任务固有复杂性与呈现造成的混乱。功能少、屏幕空白、点击少均不能单独证明体验更好；渐进披露也可能隐藏必需状态。

涉及删功能，先建立活动、岗位和功能依赖的对应：哪些支持常见活动，哪些虽少见却承担关键例外、恢复或既定义务。删除候选须说明冗余证据、替代路径、受影响者，以及何种任务受损会撤回删除；低使用率只能提示调查，不能单独证明无价值。资料不足时先提可逆整理方案，待验证后决定删除。这是本skill推导的操作规则，不是诺曼原话。

情感三层分别问：

- **本能层（visceral）**：第一感觉、感官品质、立即吸引或排斥。
- **行为层（behavioral）**：使用时的能力、控制、流畅与反馈。
- **反思层（reflective）**：身份、意义、信任、使用后的记忆与价值判断。

这是分析镜片，不是三块独立脑区或万能评分模型。把三层冲突具体化：漂亮的入口是否掩盖后果？高效流程是否剥夺控制？值得珍藏的物品是否难以维修？在不同人群和使用阶段验证，不拿“喜欢”替代任务成功，也不拿任务成功替代尊严和意义。

## D. 服务、组织与社会技术系统

画一条端到端活动链，标出人、机器、规则、数据、交接、失败后的承担者；先给系统边界，再写哪些相邻活动暂未纳入。局部速度改善可能只是把工作转给客服、家庭成员或社区。

提问：谁决定问题？谁有资源？谁有否决权？谁能退出？自动化正常时谁受益，异常时谁理解状态、接管并恢复？不要把新增的人工兜底假设为免费且无限。

输出一个近期可行步骤与一个结构性改变。分别标出负责人、资源依赖、影响范围与反馈指标；无法控制的组织因素作为限制，不把重画界面宣称为解决制度问题。

## E. 人类中心、社区与长期影响

扩展对象：直接使用者、非使用者、劳动者、被排除群体、未来人群、其他生命与物理环境。把“更可持续”变成可观察问题：材料、维修、寿命、回收、供应链、资源与成本转移。不存在数据时不编造碳或社会影响数字。

区分访谈、共同设计和社区决策权。谁代表社区、谁缺席、参与是否有补偿、反馈如何改变预算或方案、社区能否拒绝或维护成果，都比开一场工作坊更能检验参与是否真实。

先做社区认可、可逆的小规模试验，检验使用结果、负担分配、长期维护与副作用。受影响群体相互冲突时列出权利、利益和谁决定取舍；“为了人类”不能掩盖权力分配。小试成功不是全系统长期有效的证明。

## 输出强度

一句诊断应能追溯到：**观察 → 机制假设 → 改变 → 验证**。短问答可压缩成一段；评审可用表格。数字阈值随任务和风险确定，不能机械指定固定人数或成功率。
